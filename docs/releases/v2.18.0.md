Changes since [v2.17.4](https://github.com/RobinMJD/QuickPIM-PlusPlus/releases/tag/v2.17.4).

## Changelog

This release completes a broad lifecycle, concurrency, recovery, and distribution hardening pass.

### Request reliability

- Made activation and deactivation operations durable across popup closure, service-worker suspension, and browser restart.
- Added per-item checkpoints so accepted or uncertain Microsoft requests are reconciled instead of blindly resent.
- Prevented duplicate, conflicting, ambiguous, or cross-tenant result identities from targeting or clearing the wrong role.
- Preserved successful Microsoft writes when a later cache refresh or local tracking step fails.

### Access and performance

- Hardened portal-token capture, tenant/principal matching, managed recovery tabs, authentication handoff, and target-specific diagnostics.
- Kept partial Entra, PIM Group, and Azure results usable when another source or optional enrichment fails.
- Added cancellation and bounded retries for timed-out Microsoft reads while preserving valid cached data.
- Serialized progressive cache writes so slower source completions cannot overwrite newer snapshots.

### Sync, settings, and notifications

- Strengthened Browser Sync generation validation, quota accounting, concurrent merge behavior, purge/resume tombstones, and stale-device handling.
- Made settings mutations, backup restore, tracked-request restore, and reset recovery atomic across extension contexts.
- Improved expiry-reminder scheduling, permission recovery, missed-alarm catch-up, delivery backoff, and diagnostics.
- Added bounded retention and sanitization across history, references, operations, request records, and imported backups.

### Popup and distribution

- Prevented rapid mixed-mode selections, permanently stuck operation polling, stale quiet-refresh errors, and duplicate result counting.
- Made build metadata and Store packages reproducible within a build environment.
- Added manifest/HTML asset validation, package-content allowlisting, broader Edge API compatibility detection, and bounded Store API timeouts.
- Continued shipping one verified Manifest V3 archive to Chrome Web Store and Microsoft Edge Add-ons.

## Validation

- 514 unit and component tests across 44 files.
- 8 Playwright interaction and layout flows.
- TypeScript, production build, dependency audit, Edge compatibility, Edge sideload smoke, deterministic package repeat, and dual-Store release workflows passed.
