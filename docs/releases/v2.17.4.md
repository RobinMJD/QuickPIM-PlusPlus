Changes since [v2.17.0](https://github.com/RobinMJD/QuickPIM-PlusPlus/releases/tag/v2.17.0).

## Changelog

### v2.17.4

- Stabilized the Browser Sync UI regression test by waiting for the actual interactive control instead of treating a started background call as proof that React had rendered it.
- Decoupled shared Chromium Store packaging tests from the current app version, preventing stale hard-coded assertions from blocking future releases.

### v2.17.3

- Queued Settings refresh requests made during initial page hydration so early clicks are no longer lost on slower computers or CI runners.
- Serialized eligible-item refreshes, access rechecks, and pending preference saves so concurrent Settings actions cannot overwrite or interleave one another.
- Prevented duplicate Access Setup and portal recheck operations while preserving the final recovery status before controls become available again.
- Added deterministic delayed-hydration regression coverage and repeated stress verification for the Settings startup path.

### v2.17.2

- Hardened background activation and deactivation operations so popup closure, worker restarts, and repeated messages do not create duplicate privileged-access requests.
- Improved operation journaling, request identifiers, retry handling, token freshness checks, and recovery from interrupted background work.
- Serialized Browser Sync, request tracking, portal-token refresh, and background pre-refresh follow-up work to avoid stale or overlapping results.
- Strengthened reset handling around in-flight work and synchronized cleanup.
- Refined Browser Sync controls and installation layout for clearer state and more consistent spacing.

This release includes all changes since v2.17.0 because v2.17.2 and v2.17.3 were stopped by release verification before Store publication.
